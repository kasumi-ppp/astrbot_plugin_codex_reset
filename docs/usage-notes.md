本文件承接 README 中不便展开的四类细节：**权限模型、只读模式、`uncertain` 语义、群级配置覆盖**。
只描述「行为是什么」，不描述实现原理；实现细节见

## 1. 权限模型

1. 修改与诊断类命令（`subscribe / unsubscribe / settings / set / groups / test`）要求
   `event.is_admin()` 为真；普通成员执行时返回「仅管理员可执行该指令。使用 /cr help 查看权限说明。」
   并照常放行查询类命令。
2. **订阅必须来自真实群会话**：私聊执行 `/cr subscribe` 会被拒绝（禁止用裸群号拼接 umo）。
3. V1.2 不做 QQ 群主/群管授权；`admin_only_subscription=false` 仅为预留字段，**不会**放宽权限。
4. 所有管理动作写入审计日志（`operator_id / umo 指纹 / action / result / UTC 时间`，无消息正文）。
5. 限频按 `(umo, 子命令)` 计数，命中后回复剩余秒数且**不触发**任何上游请求。
6. **只读模式**：同一 `data_dir` 上检测到另一个实例仍在运行（心跳新鲜，且没有**由它自己写出**的
   干净退出标记）时，本实例只提供查询，`/cr subscribe`、`/cr unsubscribe`、`/cr set` 统一回复
   「只读模式」提示，不写任何事件、不建投递、不写心跳、不改 owner。避免两个实例互相覆盖配置。

`/cr report` 与 `/cr test image` 同属管理员命令，但在**未订阅**群也能执行——它们是手动/测试通道，
与 `/cr test` 语义一致（由管理员主动触发，不算推送），只是不会产生自动日报。

## 2. 只读模式与 shutdown_at

### 2.1 什么时候会变成只读

插件启动时会读取 `meta` 表里的 `runtime:owner` 与 `runtime:heartbeat_at`：

- 若库里有另一个实例的 owner，且它的心跳仍然新鲜（阈值 120s），且**它自己没有写过退出标记**，
  本实例就判定自己为只读实例，只提供查询，不采集、不投递、不发日报。
- 只读判定是**一次性**的。若持锁实例在本实例启动**之后**才崩溃，本实例不会自动转为主实例，
  需要再重启一次。这不会产生两个写者，也不会损坏数据。

### 2.2 `runtime:shutdown_at` 的身份语义

该 meta 键的值形如 `{owner}|{ISO 时间}`，例如：

```
codex-reset@<hostname>#<boot_id>|2026-10-22T01:30:00+00:00
```

- 只有「记录里那个 owner 自己写的退出标记」才允许下一次启动据此接管。
- 因此**只读实例退出时不会**把仍在运行的实例「洗白」成已退出。
- 旧格式（纯时间戳，无 `|` 与 owner）**不被信任**：从更早的内部测试版本升级后，首次启动可能
  判定为只读，正常重启一次即可接管。

### 2.3 常见处置

| 现象 | 处置 |
|---|---|
| 指令回「只读模式」 | 同一 `data_dir` 上还有另一个 AstrBot 实例在跑（或上次异常退出没写退出标记）。停止多余实例即可 |
| 确认只有一个实例仍只读 | 重启一次该实例；重启会写入新格式退出标记并重新接管 |
| 想彻底重置 | 停止插件 → 删除 `codex_reset.db*` 与 `audit/` → 重启并重新 `/cr subscribe` |

更多真实环境操作见 [`ACCEPTANCE-RUNBOOK.md`](ACCEPTANCE-RUNBOOK.md) §F-1；
相关已知限制（L-1 / L-3 / L-4）见 [`ACCEPTANCE.md#31-已知限制上线前请知悉`](ACCEPTANCE.md#31-已知限制上线前请知悉)。

## 3. `uncertain` 语义

`uncertain` 是投递的**终态**：不重试、不累加错误率，仅作为可观测信号。

- **什么时候会进 `uncertain`**：发送超时（结果未知）或重启时残留的 `inflight` 会被统一转为
  `uncertain`。此时消息**可能已经送达**，因此插件不再自动重发——盲目重发会造成重复刷屏。
- **代价**：极端情况下可能漏一条通知。可用 `/cr groups` 查看 `uncertain` 计数，用
  `/cr history` 人工补查。
- **每日预测图片同样遵守该语义**：图片发送超时（结果未知）时记为 `uncertain`，并且**不会**
  补发文本卡片——因为文本可能和已送达的图片构成重复消息。只有**明确失败**（渲染异常、
  QQ 适配器返回发送失败）才会降级为文本。

### exactly-once 不可保证

QQ/OneBot 侧发送超时或进程被强杀时，消息可能已送达但未被确认，插件会把该条记为 `uncertain`
并**不自动重发**（避免重复刷屏），因此极端情况下可能漏一条。可用 `/cr groups` 查看
`uncertain` 计数。

## 4. 群级覆盖与全局默认

**有效配置 = 全局默认 ⊕ 群级覆盖**：`subscriptions.settings_json` 只保存「显式覆盖过」的字段，
未覆盖字段继续继承全局默认，因此调整全局默认会自动影响所有未覆盖的群。

WebUI 卡片只是编辑入口，**数据库始终是唯一真源**；卡片 `_version` 与库中 `version` 不一致时视为
过期并忽略（不会覆盖数据库），卡片缺失则下次启动按库重新投影回填。

`/cr set` 把某个值改回全局默认时，会**删除**该覆盖字段，重新回到「继承」语义。

### 4.1 每日预测图片的两级开关

每日预测图片采用**全局总开关 + 群级开关**两级：

- `enable_daily_report=false`（默认）时任何群都不发送；
- 全局开启后，还需对本群执行 `/cr set daily on` 才会发送（订阅动作本身不会自动打开日报）；
- `/cr report` 与 `/cr test image` 是手动/测试通道，**不受**这两级开关约束，也不消耗当日自动额度。

升级时新功能默认关闭，避免对已有订阅群突然产生额外消息。

### 4.2 每日图片的补发与去重

- 按 `(群, 业务日期)` 至多一张，数据库主键兜底，重启后当天不会重复发送；
- 明确失败按 `daily_report_retry_minutes`（默认 5 分钟）重试；
- 超过 `daily_report_expiry_minutes`（默认 30 分钟）到期窗口后跳过当日报告，避免在不合适的时间
  推送过期内容；
- 源端数据超过 `max_source_age_minutes` 视为陈旧，当日跳过并记录 `skipped`，宁可不发也不发旧数据。

业务日期以 `daily_report_timezone` 为准；跨时区迁移或修改该配置，可能造成当天重复或跳过一次。
